Open Orbital to enter Mission control. The Hub is entirely in English and uses a dark theme. The left navigation opens the simulation workspace, mission library, numerical analysis, mission editor, client collections, assessments and settings. Ctrl K opens the command center. Keys 1 through 6 select modules. Space runs or pauses the advanced flight workspace when no field or dialog is active. Escape closes dialogs.

Mission control starts paused with two synthetic spacecraft. Select a spacecraft in the inspector or the asset list. Drag the Earth view to rotate and scroll to zoom. Ground track projects the numerical forecast onto the Earth surface. The inspector displays current osculating orbital elements and state vectors. Graphics use real historical photographic composites stored with the application.

Add spacecraft opens the orbital elements and vehicle properties form. Plan maneuver schedules an impulsive velocity change or finite thrust burn. Mission elapsed start is measured in seconds from the workspace epoch. Finite burn thrust is in newtons and duration in seconds. Propellant estimates are displayed before scheduling. The kernel rejects overlapping burns for one spacecraft and prevents mass below dry mass. Remove a future maneuver from the plan table. The timeline opens scheduled maneuvers for editing.

Run starts numerical propagation. The time scale selects simulated seconds per interface second. Advance 60 seconds performs a single explicit step. The flight plan updates its executed state and the event log records maneuvers and entry. Telemetry charts use computed states. Export telemetry CSV downloads the sampled vectors, mass, altitude and delta V. Reset returns all configured spacecraft to their initial orbital elements; export the flight first to preserve the current journal.

Flight dynamics exposes seeded trajectory dispersion and the propagated altitude forecast. Configure initial state uncertainty, sample count, seed and forecast horizon, then run analysis. The calculation executes in a web worker. Results report empirical position errors relative to nominal propagation and can be exported. Closest approach is a sampled separation estimate. Read Dynamics model before interpreting numerical results.

Export flight downloads the exact initial state definition and command journal. Import replays and validates an archive before restoring it. The browser saves the journal locally every five seconds. Save verified checkpoint submits the archive to the API, which independently replays it and binds the computed state digest to its signed audit chain. Workspace settings lists the authorized checkpoints with restore controls. Without the API, device simulation and file exchange remain available, while server checkpoint operations report connection errors.

The mission library has twelve executable templates across transfer, docking, recovery, deorbit, inspection and separation. Search or filter by family and client. Launch mission starts the selected executor. Docking, recovery and deorbiting open the advanced mission workspace. Transfer retains guided impulse planning, coast to apogee and circularization. Inspection and separation retain their educational linear relative motion model, which is disclosed in the exercise.

For docking, acquire the numbered holds in order. Each command applies finite guidance thrust until measured position and speed satisfy the hold criteria, or a resource limit prevents completion. A pending hold is not credited simply because the command was issued. The capture indicators show corridor, distance, speed and rotation conditions. Soft capture becomes available only after every hold and every capture condition is met. Manual control applies a signed impulse on the radial, along track or cross track axis. Propagate advances the actual states. An approach outside the corridor can later capture but does not receive full docking achievement.

For recovery, synchronize roll before the final approach. The target remains passive and its rotation is represented by the disclosed scalar attitude model. Synchronization advances 60 simulated seconds with bounded control; it does not instantly assign a successful state. Then acquire the ordered holds and verify relative speed, roll error and roll rate before soft capture. The model does not simulate a mechanical grapple or target detumbling. Abort ends an attempt and prevents further commands. A collision, capture or entry also ends the attempt.

For deorbiting, choose finite thrust or an impulsive maneuver. Set thrust in newtons for the finite option, then execute the deorbit burn. Inspect the resulting perigee, delta V and propellant use. Coast to entry interface propagates until the descending 120 km event or the requested coast duration. Completion requires the configured minimum descent rate as well as the burn and lowered perigee. The event records time, altitude and radial velocity. No atmospheric flight or ground impact is calculated.

After action shows the computed assessment, measured conditions, resource expenditure, deviations, recommendation and command journal. Move the replay control or select an earlier command to inspect its state. Historical views cannot issue live commands. Live state returns to the current authoritative session. Export assessment saves the report with scenario and journal. Export archive saves the replay inputs. New attempt preserves the prior signed server run; export a device archive before replacing a device attempt. Mission assessments lists authorized signed advanced runs and opens their original mission revisions.

Mission designer opens a new definition. Choose the family and client, edit the numerical parameters and exactly three learning objectives, then save. Configure advanced scenario exposes epoch, gravity, drag, vehicle properties, initial relative motion, ordered hold points, corridor, capture conditions and scalar rotation settings for the new mission families. Main altitude, inclination, range, speed, tolerance and budget fields stay consistent with the detailed scenario. Validation rejects inconsistent or unsafe definitions. Each save creates a revision. Changing objective wording retains the selected family's numerical rubric.

Client workspaces creates collections, assigns independent template copies, updates naming and accent, and exports a scoped library or signed offline package. Library versions restores prior definitions into a new revision. Client grouping organizes content inside the current tenant and does not create a separate access boundary. Existing signed runs keep the snapshot used when they were launched.

When the mission service is present, advanced execution uses its signed workspace record. An expired login, changed library revision, stale command sequence or missing signed record produces an error rather than silently switching to an unsigned result. Reload saved run refreshes an accepted server state after a connection failure. A device calculation is available in an offline delivery without the service, using the same kernel in a worker. Reconnecting is required to restore a run that was originally created on the server. Device exports are reproducible calculation records, not server signed assessments.

Workspace settings controls display density and flight checkpoint restoration. The interface theme is Dark and the language is English. API status reports the actual identity connection. Production federation requires configured institutional endpoints. Local development identity must not be used for classified or real operational data. The documentation states the model limits and the remaining deployment requirements.

Desktop and mobile layouts share the same calculations. Compatible browsers can request WebXR immersive rendering from orbital training, subject to headset support and a secure browser context. Full headset interaction is not validated. Three dimensional graphics can fail independently of the numerical model; the ground track and telemetry remain the fallback inspection tools.
