M1 supports one API instance with persistent storage and a web server behind HTTPS termination. Separate staging and production using distinct namespaces, identities, keys, volumes and endpoints. Local demo mode must not process real institutional information.

Local mode generates a development audit key in the data directory. Production requires a preprovisioned EC P256 PKCS8 private key named audit-key.pem in DATA_DIR, accessible only to the service account. No secret is embedded in source. Do not reuse a development key in production. External key custody and multi-epoch rotation remain M5 work. M1 key replacement requires shutdown, verified archive export and a fresh archive.

Configure NODE_ENV=production, HOST, PORT, DATA_DIR, WEB_ORIGIN, OIDC_ISSUER, OIDC_AUDIENCE and OIDC_JWKS_URI. Browser SSO additionally needs OIDC_AUTHORIZATION_ENDPOINT, OIDC_TOKEN_ENDPOINT, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET and OIDC_REDIRECT_URI. Register the exact callback URI ending in /v1/auth/callback. OIDC_MFA_ACR selects the required MFA policy. Access JWTs must contain sub, iss, aud, iat, exp, amr, tenant, roles, clearance and compartments, with mfa in amr. Training sessions require the training compartment. AUDIT_TENANT identifies the administrative tenant allowed to export the global audit, which may include other tenants and must remain restricted to central audit staff.

Do not expose the API port externally. The HTTPS perimeter proxy must preserve Origin, handle WebSocket upgrades and impose HSTS, connection limits, body limits and timeouts. The compiled web server forwards REST but not WebSocket upgrades, so route streams through the perimeter proxy. The M1 browser uses REST; streams serve observers and integrations. WebSocket authentication accepts SSO cookies or bearer headers with matching Origin. Connections expire within fifteen minutes.

The Dockerfile builds, tests and prunes development dependencies before producing a nonroot runtime. Compose requires explicit configuration and an internal network. Initialize volume ownership to UID 1000 and provision the audit key before startup. Provide controlled access to internal identity endpoints. Kubernetes supplies a staging namespace, single replica, service and default-deny policy. It is a baseline requiring orbital-data PVC, orbital-config ConfigMap, web service, TLS gateway and explicit DNS, identity and ingress policies. It is not a complete institutional deployment. Terraform and Helm remain M3 until infrastructure targets are known.

infra/ci.yaml is a template for an isolated runner. Activate it in the repository workflow location after internal review. It requires approved Node, Docker, Syft, Grype and Cosign installations. Signing uses a runner key without uploading to a public transparency log. The application SBOM is generated during build; Syft additionally inventories the image OS. The Dockerfile uses a portable base tag; pin an approved digest before promotion and update it through change control. No SLSA level or binary-reproducible build is claimed without independent artifact comparison and builder attestation.

For offline updates, prepare image, source archive excluding .data and node_modules, lockfile, SBOM, license notices, SHA256 digest and signature in the build perimeter. Transfer using approved media, verify with an already trusted public key, compare digests, scan internally, load the image and stage first. The isolated segment does not need npm install when it receives a prebuilt image. Physical air-gap operation remains an M5 validation gate.

For backup, stop mutations and the API, then copy sessions, audit and key recovery material together to encrypted storage in the same perimeter. Preserve an external digest and chain of custody. Restore to a separate environment with a dedicated identity, verify startup audit validation and replay a sample session to compare its state and receipt. Proposed RPO is 24 hours and RTO is 4 hours; neither is measured or guaranteed. Do not copy a writing volume without a consistent snapshot. Persistence and integrity errors require shutdown and audit reconciliation, not record deletion.

OpenTelemetry traces require OTEL_EXPORTER_OTLP_ENDPOINT and OTEL_EGRESS_APPROVED=true. Use an internal collector. HTTP logs are structured JSON without tokens, bodies or cookies. Process and infrastructure metrics require perimeter collectors and dashboards. Add alerts for integrity failure, authentication failure, saturation and disk pressure before institutional use. Local mode provides no SLA.
