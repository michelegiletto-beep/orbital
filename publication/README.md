Orbital publication package

Prepared on 17 October 2026 for Michele Giletto. This directory contains publication sources and a commercial assessment. External destinations are recorded only after verification in release-evidence.json. No DOI, public repository, customer adoption, independent validation or certification is asserted here.

The LinkedIn article, post and Projects description are Italian copy intended for direct use after the release evidence is accepted. They contain no slogans, hashtags, decorative headings or invented customer outcomes. Their paragraphs describe the implemented workflow, its intended buyer and its limits. The included mission screenshot shows the actual 0.3 device calculation after its first axial docking hold. linkedin-image-alt.txt describes that image in Italian. Links belong in the LinkedIn link field or the first comment after actual public destinations exist.

The English GitHub text is in github-readme.md and github-release.md. The technical paper source is technical-paper.md. The rendered report is produced by render-paper.py. The paper describes the engineering training scope and verification method; the final release evidence remains in the versioned validation report rather than being inferred from screenshots.

market-readiness.md records the commercial inference and the evidence behind it. publication-checklist.md defines the release gate. zenodo-record.json is a preparation record, not an API request: it intentionally omits an unassigned DOI, unverified affiliation, invented ORCID and future publication date. CITATION.cff identifies version 0.3.0 without inventing a DOI or repository URL. model-evidence.json contains nine synthetic measured cases with exact replay; measure-release.ts regenerates them from the current kernel using node with the tsx import hook.

The proprietary LICENSE and its approved EVALUATION.md exception remain authoritative. The exception grants 30 days of internal nonoperational evaluation and local scenario creation. Do not apply Zenodo's default Creative Commons license to the software. Preserve third party notices. A public GitHub repository also permits platform viewing and forking under GitHub's terms.

To regenerate the report, install the pinned publication requirements with Python, then run render-paper.py, verify-publication.py and build-package.py in that order. The renderer uses Arial when installed on Windows and ReportLab's bundled Vera otherwise; font substitution can change pagination. Install Poppler for PNG rendering. The script searches PATH and the optional Codex bundled runtime location. The software application does not require these publication dependencies. PDF bytes include document metadata and should be hashed after the final render; this is a re-renderable source workflow, not a claim of bit identical PDF generation across fonts or platforms.

Keep private customer collections, working session records, identity configuration, local audit keys and environment files out of every public artifact. Use only the synthetic general catalog and purpose made demonstration records.
